# 夜通しの記録 (2026-11-11 夜 〜 翌朝)

目標: 計算量 LLM の 1/10,000 で LLM に並ぶ 国産の数え上げ型 AI。 Transformer なし、 課題ごとの作り込みなし、 借りた返事は能力に数えない。
夜の方針: (1) 小型 LLM と 索引の 差の中身を 語ごとに測る (2) 対数で足す特徴の枠組みを 語数 24M / 96M で測る (3) ダメなら 原因を分析して 次の案。

## 昼までの確定した数字
- 100億語の索引 vs 小型 LLM (bit/byte, 同じ文書, 小さいほど良い): en_edu 索引 1.429 (+文書内の一致 1.407) / GPT-2 1.044 / SmolLM2-135M 0.883 / SmolLM2-360M 0.814 / Qwen2.5-0.5B 0.848。

- 損失の集中: 一度も前に出ていない語と、 最高次数の文脈で 正解が続きに無い位置が 損失の 6〜7 割。
- 話題の手がかり (直前 64 語でいちばん珍しい語): 24M 語で 得 0.03 bit/語 (0.4%)。 弱い。
- ほころびマッチ (1語違いの文脈の続きを 対数で足す, L=8): 24M 語 得 0.012 → 96M 語 得 0.026 bit/語。 語数 4 倍で 約 2.2 倍に伸びる (他の足し込みは 縮んだ)。 ただし 0.4% で 小さい。
- 平均で混ぜる方式では ほころびは 効かない (弱い証拠が 薄まる)。 対数で足す方式が必要。

- 結論: 加算特徴 (文書・アライメント・会話n-gram) では 約 4% の ビット改善。 会話に 必要な 「質問の 意味を 受けて 答えの 内容を 決める」 仕組みは 数え上げの 加算では 出ない。 次の 候補: 質問→答えの 内容語を 数える 条件付き予測 (質問の 内容語集合 → 答えの 語の 分布; 検索ではなく 語の 同時出現の 数え上げ) と、 返答の 型 (挨拶・説明・コード) を 潜在変数に した 混合。
- qa_svd (質問の 内容語 → 答えの 語, 隣接発話の PMI SVD rank 64, 24M 基準, リークなし 205 会話): 質問語のみ 10.35 bit (基準 10.47), 全部 5.755 (質問語なし 5.784)。 利得 0.5%: 語の 同時出現 だけでは 答えの 内容は 選べない。
- 次: 知識が 索引に あるのに 質問の 形では 引けない のでは? → 質問を 宣言文の 書き出し (「日本の首都は」) に 直して 索引で 続ける 探り (job_probe)。
- 知識の探り (10B 索引, 宣言文 vs 質問文): 宣言文の 書き出し なら 「日本の首都は」→東京, 「The capital of France is」→Paris(0.55), 「富士山の高さは」→3,776, 「水の化学式は」→H。 質問文の 形 (「日本の首都はどこですか？」) では 次の語が 東京(0.12) でも 続きが 崩れる (コンゴ共和国…)。 英語の 質問文は Par(0.66) まで 出る。 → 知識は 索引に ある。 欠けているのは 「質問 → 答えを 引く 書き出し」 への 変換 と 答えで 止まる こと。
- 案: 質問の 末尾の 「質問らしさ」 を 対話データの 数え上げで 学び (ユーザー発話の 末尾に 出る 語 vs 回答に 出る 語の 比), それを 剥がして 宣言文の 書き出しを 作り 索引で 続ける。 手書きの 規則は 使わない。 測定: 事実の 質問 55 問 (日本語) の 正答含有率。
- 宣言文の 書き出し (質問らしさ q(w) = 対話データの ユーザー発話の 末尾 8 語 vs 回答の 先頭 30 語 の 対数比, 数え上げ) を 剥がして 10B 索引で 貪欲に 続ける: 事実質問 日本語 56 問の 正答含有率 質問そのまま 9% (5/56) → 末尾を剥がす 25% (14/56)。 英語 20 問: 20% → 20〜25%。 ※ 「質問そのまま」 は 全部の 国の 首都に 「東京は、日本国の首都です。」 と 答える (頻出の 答えへの 張り付き)。 剥がすと 「？」 「どこでしょう？」 と 質問を 続ける 失敗が 多い → 質問語の 生成を q(w) で 罰する 版 (job_stem2) を 実行。
- stem + 質問語の 罰 (q(w) で 生成を 罰す, 数え上げのみ, 10B 索引, 貪欲): 日本語 事実質問 56 問の 正答含有率: 質問そのまま 9% → 末尾を剥がす 25% → 末尾を剥がす + 罰 1.0 36% → + 罰 2.0 38% (21/56)。 ※ 含有判定は 緩い (「O」 など 1 文字の 答えが 無関係な 文に 偶然 含まれる ことが ある)。 英語は 通信切断で 未完。 失敗の 型: 「、」 「は、」 で 始まって 話題が 飛ぶ / 「何ですか」 型で 答えの 語を 出さず 別の 文脈へ。
- 確信度 (生成の 平均対数確率) で 剥がし方を 選ぶ: 10/56 (固定の 末尾1.0+罰2.0 は 21/56)。 候補の どれか 1 つでも 当たる 上限も 21/56 → 剥がし方の 変種を 増やしても 利得なし。 確信度は 流暢な 無関係文を 選んでしまう。 (英語は Colab の 接続切断で 未取得)
- 現状の 到達点 (10B 索引, 索引外の 評価): 会話の 返答の 語の 予測 3.50→3.35 bit / 事実質問 (日本語 56 問) 9→38% (含有判定は 緩い) / 名前の 記憶 -10.6→-9.1 (対数確率)。 会話には ならない。
