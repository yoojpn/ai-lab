# 構想: 疎な表だけで作る、安くて賢い言語モデル (2026-11-01 時点)

## 1. 目的と制約
- 目的: LLM に並ぶ賢さを、桁違いに安く作る。最終的に数兆語・数兆パラメータ規模まで伸ばす。
- 制約 (ユーザー指示):
  - 数え上げ + 疎な表引きが中心。**密なニューラル層 (LLM 型) は使わない・提案しない。**
  - 勾配を使うのは「引いた行だけへの疎な逆伝播」まで。
  - 人間が書いた公開データだけを使う。有料の計算は承認制 (A100 58円/時間, 1ドル=150円)。
  - 実験は GitHub Actions (無料, 並列) で行う。手元は軽い確認だけ。

## 2. 設計の根拠 (机上で決まること)
1. 効率は「疎な参照」から出る。1語あたり (層数 × 引く行数 × 次元) だけ計算し、表の大きさに依存しない。
2. 汎化には共有が必要。完全一致の表は指数的にデータが要る。パラメータ ≪ データにして、規則を見つけさせる。
3. 深さは「小さな合成の繰り返し」で作る。多段の推論は、手順を書き出す形 (データ) で 1 段ずつ解く。
4. 誤差の割り当てが安い形でなければ、深くできない。疎な逆伝播 (引いた行だけ) か、EM の責任度。

## 3. 仕組み
- 入力: 語を BPE (3.2 万語彙) の番号にする。
- 層: 各層は表引き。前の層の出力から数個のキー (ハッシュ) を作り、次の層の表を引いてベクトルを足し合わせる。
  語の組・飛び飛びの語を使うキーで、文脈の組み合わせと位置の間の情報交換を作る。
- 出力: 次の語の確率 (最上層のベクトルと語の埋め込みの内積 → 確率)。
- 学習: 初期値は回数から作る (共起の分解など)。引いた行だけに逆伝播をかける。データは 1 周のストリーミング
  (各塊を先に予測して損失を記録し、そのあと更新)。過学習が起こらず、学習曲線がそのまま出る。
- 微調整: 質問と答えの組で、小さな表 (質問のクラス → 返事のクラス) を更新する。少数の例が見ていない質問にも効く。
- 事実: 質問を「答えが続く形の文」に直し、記憶の表から続きを引く。多段は三つ組 (主語, 関係, 目的語) の表を辿る (候補)。

## 4. 費用 (式と単価)
- 数え上げ: 約 5×10⁻¹⁰ 円/語 (0.47 マイクロ秒/語/コア × 4円/コア時間)。2 兆語で約 1,000 円。
- 疎な表のみ (密な層なし): 約 1×10⁻⁸ 円/語 (CPU 10 万語/秒/コアの仮定)。記憶 100B・2 兆語で約 2.2 万円。
  未算入: 400〜600GB のメモリの機械の費用、疎なアクセスの実測速度。
- 参考 (作らない): 密な 100B・2 兆語 = 6×N×D = 1.2×10²⁴ FLOP ≈ 1.6 億円。

## 5. これまでの実験で確定したこと
- 強い n-gram (3.8 億語, 6.31 bit/token) の上に足せた分は、どの数え上げ系も 0.034 bit (0.5%) 以下:
  規則被覆、決定木 (0.008)、低ランク線形 (0.02)、ランダム特徴 (0.004)、閉形式の層の積み重ね (0.008)、
  潜在クラス: 足し算 0.034 / 掛け算 0.009 / クラス 3-gram 0.011。
- 勾配の MLP でも、同じ入力・同じ規模なら利得は +0.002 bit しか違わない → 入力と形が上限。
- 弱い n-gram (1000 万語) の上では潜在クラスの上乗せが 0.111 bit だったが、強いベースで約 1/3 に縮む。
- 頻度を混ぜるだけで 0.06 bit 取れる (n-gram の低自信度の較正ずれ)。無料の改善。
- 学習行を 4 倍にしても上乗せのピークはほぼ変わらない (+0.002)。比率の調整では天井が上がらない。
- 検索で返す会話は、能力ではない (成果として扱わない)。

## 6. 未検証・リスク
- **疎な表だけを重ねて、深さが効くか (最大の賭け)。** 効かなければ、この形の限界。
- 数兆行規模のメモリと速度。
- 多段の推論が届くか。100 万倍の効率は未証明で、1,000 円でフロンティア級は約束できない。

## 8. 物差し
- 学習に使っていない文の bit/token と、初出の文脈の bit。
- 相手の発言を使う度合い (本物の発言と無関係な発言で、返事の確率がどれだけ変わるか)。
- 事実の質問の正解率。
- 小型 LLM (GPT-2, SmolLM2) との損失の比 (物差しとしてのみ)。
