# 研究計画: 汎用モデルを¥1万で(現在の科学を変える)

目標: 学習も推論も極端に安い汎用モデル。学習予算 ¥1万 (9.6e19 FLOP, 安い市場価格の前提。一般的H100では約3.3e19)。
データ: 人間が書いたもの + プログラムで生成したもののみ(公開モデルの出力・蒸留は使わない)。

## 変えたい常識
「1語ごとに全パラメータを掛ける密な計算が必要」「計算量は語数に比例する」

## 検証できる仮説(それぞれ、外れたら捨てる基準つき)
| # | 仮説 | 測り方 | 捨てる基準 |
|---|---|---|---|
| H1 | 計算は情報量(予測できない語)に比例させられる。難しい語の割合 f_hard は小さく、規模で増えない | e_cd: p>0.9 の語の割合、安い経路に回したときの bit 悪化 | 難しい語が全体の50%超で、規模が上がっても減らない |

| H4 | 学習の大半は書き込み(カウント/連想メモリ)で足り、NNは残差だけでよい。データが増えるほど表の担当が増える | カウント事前分布あり/なしで、同じ bit に必要なNNサイズ | 事前分布ありでも必要サイズが変わらない |

## 既に外れた/弱いもの(正直に)
- 知識と技能の分解(TFの優位がまれな語ほど大きい)は支持されなかった。
- 全部成功で中心30倍、は過大。実測は小規模で2〜3.5倍、幅で縮む傾向。
- Rho、SOAP、loop(共有層)、Dyck(この小規模)は悪化または効果なし。

## 段階
G1 幅スケールで利得が保たれる(H2) → G2 索引を大きくすると知識が下がり続ける → G3 Q/K低次元(H3) → G4 検証付きRL(H5)。
各段階は無料CPUで判定する。有料GPUは、費用の式と承認がそろってから。

## 推論・コーディング(追加)
考え方: 「推論 = 実行できるコードを書き、実行して確かめること」。計算は実行系に任せ、コアはコードと言語を担う。
根拠(取得して確認): PAL は算術・記号計算をPython実行系に渡し、GSM8Kで PaLM の CoT を絶対値で15点上回った。
Codex は pass@1 28.8% が、100回サンプルして通るものを選ぶと 70.2%。
RLVR は主に pass@1 を上げ、pass@k の天井は上げない(要原論文確認)。つまり天井は事前学習で決まる。

## 7倍の予算表(¥1万 = 9.6e19 FLOP、Chinchilla最適。定数は記憶ベースの目安で、この環境では未測定)
L = E + A/N^0.34 + B/D^0.28。¥1万: N≈9e8, D≈1.8e10 で余剰損失 0.92 (= 0.368 + 0.553)。405B・15T語は 0.13。必要なのは、同じ計算で余剰損失を約1/7にすること。
余剰損失を f 分の1にすると、同じ品質に必要な計算は f^6.5 分の1 (f=2:90倍, 3:1300倍, 5:3.5万倍, 7:31万倍)。
| 項 | 必要な実効倍率 | 取れた実効倍率(実測) | 候補 |
|---|---|---|---|
| 実効パラメータ(知識) | x305 | 未測定 | 索引・検索(文献25〜50倍)、疎な構造 |
| 実効データ(技能) | x1100 | 未測定 | 選別(仮説X)、複数エポック(約3〜4倍)、検証できる自己生成データ(仮説Y) |
仮説X: 選別で、学習曲線(bit/語 対 log D)の傾きがランダムより20%以上緩やか。捨てる基準: 傾きの差が20%未満。(N群: n_rand/n_mid/n_hi/n_top × D=2,4,8,16M語, d128)
仮説Y: 検証できる自己生成データでの技能学習は、同FLOPの教師ありより正答率の伸びが速い。

## 方針の確定(2026-10-28、ユーザー承認)
知識は索引、技能は小さい密な核。式: C = 6·N_c·D_skill + 6·e·P + 2·N_idx·T、L = E + A_c N_c^-α + B_c D_eff^-β + R(T)。
O群: 核は D=2M/4M 語だけ学習し、索引は核が学習していない文章 T=0.25M〜6M 位置から作る。R(T) と、実効データ倍率 g_ret(同じbitに必要な密モデルの語数 D' / D)を測る。
 参照(d128の密モデル、N群ランダム): 2M 6.634 / 4M 5.936 / 8M 5.435 / 16M 5.130 bit/語。
 合格: 4M語の核+索引で 5.44 以下(=D'≥8M、g_ret≥2)。捨てる基準: 0.1 bit未満の改善。
 限界: 後づけのkNN-LM。学習中から検索するRETRO型は別。

## TRACE: 数え上げだけで「変数の値を引く」「足す」を学べるか (2026-10-31, exp_trace.py / exp_trace_als.py, ◎ 実測, おもちゃの領域)

| copy_name | off4, off5, off6, off14 | 1.0000 | 1.0000 |

### MIX 文章(Web)を足しても会話を悪化させない組み込み (exp_mix.py)  ◎測定 (新エンジン, BPE語, 4-gram WB)
- 会話: DailyDialog きれいな分割(学習1.2M語/テスト0.058M語)。 Web: CC-100 英語 約35M語(159MB, 会話と同じ小文字・記号分かち書きに揃えた)。
- 会話テスト bit/語: D(会話のみ) 6.203 / W(Webのみ) 8.269 / 単純合算 P 6.131 / 会話5回数えて合算 P5 6.094 / 静的補間(λ=0.70, 会話検証で決定) **5.676** / ベイズ混合(fixed-share α=0.1) **5.720**。
- Web テスト bit/語: W 7.372 / P 7.377 / 静的補間 7.780 (**+0.41 悪化**) / ベイズ混合 7.409 (**+0.037**)。
- 結論: 専門家ごとに別の表を持ち、 ベイズ混合で重みを語ごとに更新すれば、 会話 -0.48 bit を得ながら Web の悪化は +0.04 bit に収まる(調整は α のみ、 検証窓で選択)。 静的な補間は会話では最良だが Web を悪化させる。 単純合算は会話の利得が小さい(-0.07〜-0.11)。
- 注意: α は探索範囲の端(0.1)が選ばれた。 Wikipedia 本体は未使用(CC-100 の Web 文章)。 K=3 以上の専門家(会話/文章/コード/言語別)は未測定。

## DLG: 会話の試作 (英語の小説の会話 + 青空文庫)  ※ 2026-10-31 実測 ◎
データ: Gutenberg(en) 4.5 億語 + 青空文庫 3,375 万字の「引用符の発言」を会話化 (collect_dialog.py)。 BPE 32k (tok_dlg.py)。 本 ID で 学習/検証/テスト分割。
**重複**: 会話の 38% が完全な重複 (同じ作品の別版)。 除去前は 高次の n-gram が過信になり 5-gram(7.10) < 3-gram(6.68)、 テストへの漏れも起こしうる。
  除去 (完全一致 + 先頭 2 発言一致、 検証・テストと同じ会話は学習から除外) 後: 学習 3.82 億語 / 246 万会話。 5-gram 項目 1.73 億 -> 2,926 万。
**n-gram の修正**: 出現 1 回の項目を捨てるとき N,T は捨てる前の値、 捨てた質量 X を低次へ戻す: P = (cnt + (T+X) P_lower) / (N+T)  (engine.py)。
bit/token (テスト 95 万位置, 重複除去後):
| 構成 | bit/token |
|---|---|
| LM 3-gram | 6.560 |
| LM 5-gram | 6.503 (en 6.472, ja 7.109) |
| +キャッシュ (直近 256 語, 補間は区分ごとに格子探索) | 6.340 |
| +コピー(直前 1-2 語の前回出現の次) | 6.315 |
| +規則被覆 (4 通りの特徴の組) | 6.314 (規則 1〜7 本、発火 0.3〜0.9%) |
規則被覆が見つけた規則は 「can’ -> t」「there’ -> s」のような綴り・縮約の規則だけ。 会話の意味に関わる決定的な規則は見つからなかった (自然な会話に純度 90% の文脈はほとんどない)。
1-of-100 返答検索 (英語 400 会話, PMI 採点, 偶然 1%): LM のみ R@1 7.8% / +キャッシュ・コピー・規則(文脈=全部) 13.8% / 同(文脈=直前の発言だけ) 9.3%
  -> 遠い文脈を使うと +4.5 点。 だが 13.8% は会話として低い。 n-gram + 局所の規則では 会話の意図・話題の追跡は取れない。
